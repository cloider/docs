These endpoints manage Cloider [object storage](/object-storage/overview) buckets: create and delete them, read their endpoint and usage, make them public or private, serve them as static websites, and set bucket policies, versioning, lifecycle and CORS rules. To read and write the files inside a bucket you normally use any S3 client with an [access key](/api/endpoints/bucket-keys); the API's own file endpoints are on [Bucket objects](/api/endpoints/bucket-objects).

All paths are relative to `https://cloider.com/api`. See [Authentication](/api/authentication) for the token header.

## The bucket object

```json
{
  "hashed_id": "b7r2x",
  "bucket_name": "acme-assets",
  "region": "eu-central-2",
  "public": true,
  "policy": null,
  "status": "Ready",
  "size_bytes": 734003200,
  "size_sampled_at": "2026-10-20T09:00:04.118230Z",
  "website": false,
  "website_index": "index.html",
  "website_error": "",
  "endpoint": "https://s3.eu-central-2.cloider.com",
  "url": "https://acme-assets.s3.eu-central-2.cloider.com",
  "website_url": "",
  "created_at": "2026-09-30T15:12:48.551021Z"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `hashed_id` | string | The bucket's id |
| `bucket_name` | string | The S3 bucket name. Unique across all of Cloider, and fixed once created |
| `region` | string | The region code, for example `eu-central-2` |
| `public` | boolean | `true` when anyone can read an object by its URL without a key. Listing stays private either way |
| `policy` | string or null | The bucket policy as you wrote it, a JSON document in a string, or `null` |
| `status` | string | `Creating`, `Ready`, `Terminating` or `Failed` |
| `size_bytes` | integer | Bytes stored, as of the last usage sample |
| `size_sampled_at` | string or null | When `size_bytes` was measured |
| `website` | boolean | `true` when the bucket is served as a [static website](/object-storage/static-websites) |
| `website_index`, `website_error` | string | The website's index document (`index.html` by default) and error document (empty for the built-in page) |
| `endpoint` | string | The region's S3 endpoint, for S3 clients |
| `url` | string | The bucket's own address, `https://<bucket>.<endpoint host>`. Public objects are at `<url>/<key>` |
| `website_url` | string | The website's address, `https://<bucket>.s3-website.eu-central-2.cloider.com`, while `website` is on, otherwise empty |
| `domains` | object list | Only from [`GET /buckets/:hashed_id`](#get-a-bucket), and only when domains serve the website: each `{"domain_name", "domain_type"}` with a Bucket target pointing at it. `domain_type` is `Subdomain` or `CustomDomain` |
| `created_at` | string | When the bucket was created |

## Create a bucket

```http
POST /buckets
```

Creates a bucket. Unlike clusters and databases, a bucket is created while the request runs, which takes a few seconds, so the answer also tells you whether the name was free.

**Access:** Read & Write token.

### Request body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `bucket_name` | string | Yes | 3 to 63 characters: lower case letters, digits and `-`, starting and ending with a letter or digit. No dots. Names are shared by every Cloider account, so pick something specific |
| `region` | string | No | A region code from `GET /buckets/regions`. Default `eu-central-2` |
| `public` | boolean | No | `true` to let anyone read objects by URL. Default `false` |
| `versioning` | boolean | No | `true` to keep every version of every object from the start. Default `false` |
| `website` | boolean | No | `true` to serve the bucket as a static website from the start, with `index.html` as its index document. Needs `public`, or the request fails with an error under `website`. Default `false` |

```bash
curl -X POST https://cloider.com/api/buckets \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"bucket_name": "acme-backups", "region": "eu-central-2", "versioning": true}'
```

```json title="Response"
{"hashed_id": "k5t1v"}
```

Check `GET /buckets/k5t1v/status` once: it is normally `Ready` right away.

### Errors

| Status | Field | Message |
| --- | --- | --- |
| `400` | `bucket_name` | `Bucket name must not be empty`, `Bucket name must be at least 3 characters`, `Bucket name must not exceed 63 characters`, `Bucket name can only have lowercase letters, numbers and "-"`, `Bucket name must start and end with a letter or a number`, `Bucket name is reserved`, `This bucket name is already taken` |
| `400` | `region` | `Invalid region` |
| `400` | `_` | `Free plan users can not create more than one bucket. UPGRADE NOW!` |
| `400` | `_` | `Your account is suspended. Upgrade to a paid plan to continue using our services.` |
| `400` | `_` | `Buckets aren't available at the moment!`, `Operation failed, Couldn't create the bucket!` |
| `403` | `_` | `This API token is read only!`, or `You have read-only access to this account, you can not create buckets!` for a Restricted member |

These names are reserved: names starting with `xn--`, `sthree-` or `amzn-s3-demo-`, names ending with `-s3alias`, `--ol-s3`, `--x-s3` or `--table-s3`, and the name `filemeta`.

## Get a bucket

```http
GET /buckets/:hashed_id
```

Returns one bucket, in the shape [above](#the-bucket-object). For a website bucket served on domains, it also has `domains`.

**Access:** any token.

```bash
curl https://cloider.com/api/buckets/s3w8q \
  -H "Authorization: Bearer $CLOIDER_TOKEN"
```

```json title="Response (trimmed)"
{
  "hashed_id": "s3w8q",
  "bucket_name": "acme-site",
  "public": true,
  "status": "Ready",
  "website": true,
  "website_index": "index.html",
  "website_error": "404.html",
  "url": "https://acme-site.s3.eu-central-2.cloider.com",
  "website_url": "https://acme-site.s3-website.eu-central-2.cloider.com",
  "domains": [
    {"domain_name": "docs.example.com", "domain_type": "CustomDomain"}
  ]
}
```

A deleted bucket, or an id of another account, answers `404 Not Found` (plain text).

## Make a bucket public or private

```http
PUT /buckets/:hashed_id/visibility
```

Makes the bucket public, so anyone can download an object from `<url>/<key>` without a key, or private again. Listing the bucket's contents always needs a key.

**Access:** Read & Write token. The bucket must be `Ready`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `public` | boolean | Yes | `true` for public, `false` for private |

```bash
curl -X PUT https://cloider.com/api/buckets/b7r2x/visibility \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"public": true}'
```

```json title="Response"
{"success": true}
```

| Status | Message |
| --- | --- |
| `400` | `The bucket must be ready to change its visibility.` |
| `400` | `The bucket's policy allows everyone ("*"), remove those statements first.` (making it private while the policy grants everyone access) |
| `400` | `The bucket's website needs it public, turn the website off first.` (making it private while its [website](#turn-the-website-on-or-off) is on) |
| `400` | `Another change to this bucket is in progress, try again in a moment!` |
| `400` | `Couldn't change the bucket's visibility, try again in a moment!` |
| `403` | `This API token is read only!`, `You have read-only access to this account, you can not change buckets!` |

See [Public and private buckets](/object-storage/public-and-private-buckets).

## Get a bucket's website

```http
GET /buckets/:hashed_id/website
```

Returns the bucket's [static website](/object-storage/static-websites) settings.

**Access:** any token.

```bash
curl https://cloider.com/api/buckets/s3w8q/website \
  -H "Authorization: Bearer $CLOIDER_TOKEN"
```

```json title="Response"
{
  "enabled": true,
  "index_document": "index.html",
  "error_document": "404.html",
  "url": "https://acme-site.s3-website.eu-central-2.cloider.com"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `enabled` | boolean | Whether the bucket is served as a website |
| `index_document` | string | The file served for `/` and every path ending in `/`, `index.html` by default |
| `error_document` | string | The key served with a `404` for anything missing. Empty for the built-in page |
| `url` | string | The website's address while `enabled`, otherwise empty |

## Turn the website on or off

```http
PUT /buckets/:hashed_id/website
```

Turns the bucket's static website on or off and sets its documents. Every field is applied, so send the ones you want to keep too. Changes take up to about 30 seconds to show on the website. To serve the website on a domain, create a [Bucket target](/api/endpoints/targets#create-a-target).

**Access:** Read & Write token. The bucket must be `Ready`, and public to turn the website on.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | Yes | `true` to serve the bucket as a website, `false` to stop |
| `index_document` | string | No | A file name without `/`, up to 255 characters. Empty means `index.html` |
| `error_document` | string | No | A key in the bucket, up to 1024 characters, not starting with `/` and without `.` or `..` segments. Empty means the built-in page |

```bash
curl -X PUT https://cloider.com/api/buckets/s3w8q/website \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"enabled": true, "index_document": "index.html", "error_document": "404.html"}'
```

The response has the shape of [`GET /buckets/:hashed_id/website`](#get-a-buckets-website).

| Status | Field | Message |
| --- | --- | --- |
| `400` | `index_document` | `The index document is a file name without a slash, like index.html` |
| `400` | `error_document` | `The error document is a key in the bucket, like 404.html, not starting with a slash` |
| `400` | `_` | `Make the bucket public first, its website is read without a key.` |
| `400` | `_` | `Domains still point at this website, remove their targets first.` (turning it off while Bucket targets point at it) |
| `400` | `_` | `The bucket must be ready to change its settings.`, `Another change to this bucket is in progress, try again in a moment!` |
| `403` | `_` | `This API token is read only!`, `You have read-only access to this account, you can not change buckets!` |

## Set a bucket policy

```http
PUT /buckets/:hashed_id/policy
```

Sets the bucket's policy, an AWS style JSON document that allows or denies S3 actions to access keys or to everyone. The policy replaces any previous one. It is checked before it is applied, and a rejected policy says why.

**Access:** Read & Write token. The bucket must be `Ready`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `policy` | string | Yes | The policy document as a **string** (JSON inside JSON), up to 16 KB. `Version` must be `2012-10-17` |

```json title="policy.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Principal": {"AWS": ["CLDR4N7TQ2WB9XK0HJ3E"]},
      "Action": ["s3:DeleteObject"],
      "Resource": ["arn:aws:s3:::acme-backups/*"]
    }
  ]
}
```

Build the request body with `jq`, which turns the file into a string:

```bash
jq -n --rawfile policy policy.json '{policy: $policy}' | \
curl -X PUT https://cloider.com/api/buckets/k5t1v/policy \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary @-
```

```json title="Response"
{"policy": "{\n  \"Version\": \"2012-10-17\",\n  \"Statement\": [ ... ]\n}"}
```

A policy that doesn't pass the checks answers `400` with the reason on `policy`, naming the statement:

```json title="Response (400)"
{
  "errors": {"policy": ["Statement 1: Action \"s3:PutBucketAcl\" can't be allowed by a policy, only object actions can"]},
  "data": null
}
```

Other messages on `policy` include `The policy is empty`, `The policy is over 16 KB`, `Version must be "2012-10-17"`, `The policy has no statements`, `Effect must be "Allow" or "Deny"`, `Principal is required`, `Action is required`, `Resource is required` and `Storage rejected the policy (...)`. General errors are `The bucket must be ready to change its policy.`, `Another change to this bucket is in progress, try again in a moment!` and `Couldn't apply the policy, try again in a moment!`.

Principals name access keys by their access key id (`CLDR...`). [Bucket policies](/object-storage/bucket-policies) explains which actions, principals and conditions are supported.

## Get the versioning status

```http
GET /buckets/:hashed_id/versioning
```

Returns whether the bucket keeps old versions of objects. It reflects changes made through the S3 API too.

**Access:** any token. The bucket must be `Ready`.

```bash
curl https://cloider.com/api/buckets/k5t1v/versioning \
  -H "Authorization: Bearer $CLOIDER_TOKEN"
```

```json title="Response"
{"status": "Enabled"}
```

`status` is `Enabled`, `Suspended` (versioning was on and is now off; existing versions are kept) or an empty string (versioning was never turned on).

## Turn versioning on or off

```http
PUT /buckets/:hashed_id/versioning
```

Turns versioning on, so every overwrite and delete keeps the previous version, or suspends it. A bucket that has had versioning can't go back to never versioned: turning it off suspends it.

**Access:** Read & Write token. The bucket must be `Ready`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | Yes | `true` to enable, `false` to suspend |

```bash
curl -X PUT https://cloider.com/api/buckets/k5t1v/versioning \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"enabled": true}'
```

```json title="Response"
{"status": "Enabled"}
```

See [Versioning](/object-storage/versioning). Old versions are stored and billed like any other data, so pair versioning with a [lifecycle rule](#replace-the-lifecycle-rules) that expires noncurrent versions.

## Get the lifecycle rules

```http
GET /buckets/:hashed_id/lifecycle
```

Returns the bucket's lifecycle rules, which delete objects, old versions and abandoned uploads after a number of days.

**Access:** any token. The bucket must be `Ready`.

```bash
curl https://cloider.com/api/buckets/k5t1v/lifecycle \
  -H "Authorization: Bearer $CLOIDER_TOKEN"
```

```json title="Response"
{
  "rules": [
    {
      "id": "expire-logs",
      "prefix": "logs/",
      "enabled": true,
      "expire_days": 30,
      "noncurrent_days": 7,
      "abort_multipart_days": 2
    }
  ],
  "unsupported_rules": 0
}
```

| Field | Description |
| --- | --- |
| `id` | The rule's name |
| `prefix` | The rule applies to keys that start with it. Empty for the whole bucket |
| `enabled` | Whether the rule is active |
| `expire_days` | Delete objects this many days after they were written. `0` for never |
| `noncurrent_days` | Delete old versions this many days after they were replaced. `0` for never |
| `abort_multipart_days` | Abort unfinished multipart uploads after this many days. `0` for never |
| `unsupported_rules` | Rules set through the S3 API with features these fields can't show, such as tag filters or transitions. They are counted, not returned |

## Replace the lifecycle rules

```http
PUT /buckets/:hashed_id/lifecycle
```

Replaces all of the bucket's lifecycle rules with the list you send, including rules set through the S3 API that the dashboard can't show. An empty list removes the lifecycle configuration.

**Access:** Read & Write token. The bucket must be `Ready`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `rules` | object list | Yes | Up to 100 rules, each with the fields above |

Each rule must have an `id` of 1 to 255 letters, digits, `.`, `_` or `-`, unique in the list; a `prefix` of at most 1024 characters without a leading `/`; and at least one of the three day counts set, each between 1 and 36500.

```bash
curl -X PUT https://cloider.com/api/buckets/k5t1v/lifecycle \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "rules": [
      {"id": "expire-logs", "prefix": "logs/", "enabled": true, "expire_days": 30, "noncurrent_days": 7, "abort_multipart_days": 2}
    ]
  }'
```

```json title="Response"
{
  "rules": [
    {"id": "expire-logs", "prefix": "logs/", "enabled": true, "expire_days": 30, "noncurrent_days": 7, "abort_multipart_days": 2}
  ],
  "unsupported_rules": 0
}
```

Validation errors are on `rules` and name the rule, for example `Rule 2: another rule already has the ID "expire-logs"`, `Rule 1: set at least one of the day counts` or `A bucket can have up to 100 lifecycle rules`. See [Lifecycle rules](/object-storage/lifecycle-rules).

## Get the CORS rules

```http
GET /buckets/:hashed_id/cors
```

Returns the bucket's CORS rules, which decide the websites that can use it from a browser. An empty list means any website can. The rule that keeps the Cloider dashboard working isn't returned.

**Access:** any token. The bucket must be `Ready`.

```bash
curl https://cloider.com/api/buckets/k5t1v/cors \
  -H "Authorization: Bearer $CLOIDER_TOKEN"
```

```json title="Response"
{
  "rules": [
    {
      "id": "web-app",
      "allowed_origins": ["https://app.example.com"],
      "allowed_methods": ["GET", "PUT"],
      "allowed_headers": ["Content-Type"],
      "expose_headers": ["ETag"],
      "max_age_seconds": 3000
    }
  ]
}
```

| Field | Description |
| --- | --- |
| `id` | The rule's name, `""` for none |
| `allowed_origins` | Origins a browser lets use the bucket, such as `https://app.example.com`. `https://*.example.com` matches its subdomains, `*` any website |
| `allowed_methods` | Any of `GET`, `HEAD`, `PUT`, `POST` and `DELETE` |
| `allowed_headers` | Request headers a page may send. `*` for any, or a prefix like `x-amz-*` |
| `expose_headers` | Response headers a page's script may read |
| `max_age_seconds` | How long browsers may reuse a preflight answer. `0` leaves it to the browser |

## Replace the CORS rules

```http
PUT /buckets/:hashed_id/cors
```

Replaces all of the bucket's CORS rules with the list you send, including rules set through the S3 API. An empty list removes the CORS configuration, so any website can use the bucket again. The rule that keeps the Cloider dashboard working is added ahead of yours.

**Access:** Read & Write token. The bucket must be `Ready`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `rules` | object list | Yes | Up to 99 rules, each with the fields above |

Each rule needs at least one origin and one method. Origins are `*` or a scheme, host and optional port without a path, with a `*` only right after the scheme; they come back in lower case, and methods in upper case. An `id` is optional, up to 255 characters, unique in the list. `max_age_seconds` is 0 to 86400.

```bash
curl -X PUT https://cloider.com/api/buckets/k5t1v/cors \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "rules": [
      {"id": "web-app", "allowed_origins": ["https://app.example.com"], "allowed_methods": ["GET", "PUT"], "allowed_headers": ["Content-Type"], "expose_headers": ["ETag"], "max_age_seconds": 3000}
    ]
  }'
```

```json title="Response"
{
  "rules": [
    {"id": "web-app", "allowed_origins": ["https://app.example.com"], "allowed_methods": ["GET", "PUT"], "allowed_headers": ["Content-Type"], "expose_headers": ["ETag"], "max_age_seconds": 3000}
  ]
}
```

Validation errors are on `rules` and name the rule, for example `Rule 1: the origin "example.com" isn't an origin like https://app.example.com`, `Rule 2: allow at least one method` or `A bucket can have up to 99 CORS rules`. See [CORS](/object-storage/cors).

## Delete a bucket

```http
DELETE /buckets/:hashed_id
```

Deletes the bucket and every object in it. This can't be undone. The bucket's policy is removed first, and the targets that point domains at its website are deleted (the domains stay), then the bucket goes to `Terminating` while its objects are deleted in the background, which can take a while for a large bucket. When it is done, the bucket disappears and its status answers `404`. The name becomes free for anyone to take.

**Access:** Read & Write token.

```bash
curl -X DELETE https://cloider.com/api/buckets/k5t1v \
  -H "Authorization: Bearer $CLOIDER_TOKEN"
```

The response is the account's bucket list, with this bucket `Terminating`.

| Status | Message |
| --- | --- |
| `400` | `This bucket is still being created!` |
| `400` | `This bucket is already being deleted!` |
| `400` | `Another change to this bucket is in progress, try again in a moment!` |
| `400` | `Couldn't remove the bucket's policy, try again in a moment!` |
| `403` | `This API token is read only!`, `You have read-only access to this account, you can not delete buckets!` |
| `404` | `Not Found` (plain text) |

See [Delete a bucket](/object-storage/delete-a-bucket).
