A custom domain is a domain you own, such as `example.com`, or a subdomain of it, such as `shop.example.com`, that you
add to Cloider to serve an [app](/apps/overview), a [Kubernetes Service](/kubernetes/expose-services) or a bucket's
[static website](/object-storage/static-websites) on it over HTTPS.
This page walks through the whole setup: adding the domain, moving its DNS to Cloider (or keeping your current DNS
provider), pointing the host names at Cloider, routing them with targets, and checking that HTTPS works.

## At a glance

| Step | What you do | Where |
| --- | --- | --- |
| 1 | Add `example.com` to Cloider | Cloider |
| 2 | Recreate the records the domain already has, such as email records | Cloider |
| 3 | Change the domain's nameservers to `ns1.cloider.com` to `ns4.cloider.com` | Your registrar |
| 4 | Point the host names you serve at Cloider with a CNAME or A record | Cloider |
| 5 | Add a target that routes the domain to an app, a Service or a bucket's website | Cloider |
| 6 | Wait for DNS and the HTTPS certificate, then check | Your terminal |

Plan for 10 minutes of work, then up to 48 hours of waiting for the nameserver change in the worst case. Most domains
are working within an hour or two.

## Before you begin

- **A registered domain.** Cloider doesn't sell domains. Buy one from any registrar, such as Namecheap, GoDaddy,
  Cloudflare, Squarespace Domains or Amazon Route 53, and keep the login: you change the nameservers there.
- **Something to serve.** A deployed [app](/apps/overview) whose status is `Ready`, a [cluster](/kubernetes/overview)
  with a Service to route to, or a public bucket with its [static website](/object-storage/static-websites) on. You can
  add the domain first and the target later.
- **Write access.** A member with read-only access, or a read-only API token, can't add domains.
- **A free subdomain you keep.** Step 4 points your host names at one of your free `cloider.app` subdomains, for example
  the one your app was created with. See [Free subdomains](/domains/free-subdomains).
- New to DNS? Read [DNS basics](/domains/dns-basics) first.

## Choose how the domain's DNS is hosted

You have two options. Both serve the domain from Cloider over HTTPS; they differ in who answers DNS for it.

| | Use Cloider's nameservers | Keep your current DNS provider |
| --- | --- | --- |
| **You change** | The nameservers, at your registrar | Nothing at the registrar |
| **Records live in** | Cloider: dashboard, CLI, Terraform, API, MCP | Your DNS provider's dashboard |
| **Good for** | Managing DNS next to your apps, as code with Terraform | Domains with many records, or DNS features Cloider doesn't have, such as DNSSEC |
| **Steps on this page** | 1 to 6 | 1, then [Keep your current DNS provider](#keep-your-current-dns-provider), then 5 and 6 |

The rest of this page follows the first option, and the second one has [its own section](#keep-your-current-dns-provider).

## Step 1: Add the domain to Cloider

Adding the domain reserves it for your account with the status `Pending`, and adds an `A` record for the domain itself
that points at Cloider (see [step 4](#step-4-point-the-host-names-you-serve-at-cloider)). Cloider doesn't check who owns
the domain or where its nameservers point at this stage.

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

1. Open **Domains** in the sidebar, click **Add Domain** and choose **Custom Domain**.
2. In **Domain or subdomain**, type the domain, for example `example.com`.
3. Click **Check Availability**. If no other account holds the domain, Cloider adds it to yours and opens the next
   step, **Add DNS records (Optional)**.

The page then guides you through the remaining steps in order: **Add DNS records (Optional)** (step 2 below),
**Activate Cloider DNS**, which lists the nameservers (step 3), and **Connect your apps**, where you add targets
(step 5). The final **Add domain** button is enabled once the domain has a target.

</TabItem>
<TabItem value="cli" label="CLI">

```bash
cloider domain create example.com
```

```text title="Output"
✓ Added example.com

  ns1.cloider.com
  ns2.cloider.com
```

Any name that doesn't end in `.cloider.app` is added as a custom domain. The CLI lowercases the name and drops a
trailing dot, so `Example.COM.` is added as `example.com`.

### Which domain names can I add?

Any domain or subdomain you control, as long as it follows these rules. The API checks them and answers with the
message shown.

| Rule | Message when broken |
| --- | --- |
| At least two labels, such as `example.com` | `Invalid domain format` |
| 3 to 253 characters | `Domain name must be at least 3 characters`, `Domain name must not exceed 253 characters` |
| Letters, digits, dots and hyphens only | `Domain name must contain only letters, numbers, dots, and hyphens` |
| No two dots in a row | `Domain name must not have consecutive dots` |
| Doesn't start or end with a dot or a hyphen | `Domain name must not start with special characters`, `Domain name must not end with special characters` |
| Not a Cloider domain (the label before the TLD isn't `cloider`) | `Disallowed domain name` |
| Not held by another Cloider account | `The domain already created by a different user, if you own this domain contact support` |
| Not a public suffix that many owners share, such as `co.uk` or `github.io` | `Domain name is a public suffix shared by many owners, add your own domain under it, such as example.co.uk` |
| Not under a domain another Cloider account holds, such as `shop.example.com` when another account has `example.com` | `This domain is under example.com, which belongs to another Cloider account. If you own example.com, contact support` |
| No domain under it held by another Cloider account | `A domain under this one belongs to another Cloider account. If you own example.com, contact support` |

Names are stored in lowercase. Internationalized names must be entered in their `xn--` (Punycode) form, since only
letters, digits, dots and hyphens are accepted.

If another account already holds a domain you own, for example a former colleague's account, contact
[support](/account/support) with proof of ownership.

## Step 2: Recreate your existing DNS records

If the domain is already in use, for example for email or a website elsewhere, copy its records into Cloider **before**
you change the nameservers. The moment the nameservers switch, only the records in Cloider answer, so any record you
didn't copy stops working.

Look up the current records in your current DNS provider's dashboard. The records most often forgotten:

| Record | Name | Why it matters |
| --- | --- | --- |
| `MX` | apex | Without it, email to `you@example.com` bounces |
| `TXT` (SPF) | apex | Without it, your mail lands in spam |
| `TXT` (DKIM) | `<selector>._domainkey` | Signs your outgoing mail |
| `TXT` (DMARC) | `_dmarc` | Your email authentication policy |
| `TXT` (verification) | apex or a service specific name | Google, Microsoft, Apple and others re-check these |
| `CNAME`, `A` | `www`, `mail`, `autodiscover`, ... | Websites and services on subdomains |
| `CAA` | apex | Which certificate authorities may issue certificates |

The apex already has an `A` record that points at Cloider. If your website stays elsewhere, add its `A` record with a
blank name: it takes the place of Cloider's.

You can also check what a name answers today with `dig`:

```bash
dig example.com MX +short
dig example.com TXT +short
dig _dmarc.example.com TXT +short
dig www.example.com +short
```

Then add each record in Cloider. In the dashboard, click **Add DNS record** on this step. With the CLI:

```bash
cloider dns create example.com --type MX --value "10 mx1.mail.example.net." --ttl 3600
cloider dns create example.com --type TXT --value "v=spf1 include:mail.example.net ~all" --ttl 3600
```

Every type and its rules are in [DNS records](/domains/dns-records), and email setups for Google Workspace and
Microsoft 365 are in [Email DNS records](/domains/email-dns-records). A brand new domain has nothing to copy, so skip
this step.

## Step 3: Change the nameservers at your registrar

Sign in to your registrar, open the domain's DNS or nameserver settings, choose custom nameservers, and enter all
four:

```text
ns1.cloider.com
ns2.cloider.com
ns3.cloider.com
ns4.cloider.com
```

Remove any other nameservers from the list. In the dashboard, the same four names are on the **Activate Cloider DNS**
step and in the **Name servers** section of the domain's page, each with a copy button.

  src="/img/screenshots/domains/custom-domain-nameservers.webp"
  url="/dashboard/domains/custom-domain"
  alt="The Activate Cloider DNS step listing ns1.cloider.com, ns2.cloider.com, ns3.cloider.com and ns4.cloider.com with copy buttons"
  caption="The Activate Cloider DNS step lists the four nameservers to set at your registrar."
/>

Step by step instructions for Namecheap, GoDaddy, Cloudflare, Squarespace Domains, Amazon Route 53 and others are in
[Nameservers](/domains/nameservers). The registry usually publishes the change within minutes to a few hours, and
resolvers can keep the old nameservers cached for up to 48 hours.

:::warning[Turn off DNSSEC at your current provider first]
If DNSSEC is enabled for the domain, turn it off (remove the DS record at the registrar) before you change the
nameservers. Cloider's nameservers don't sign answers, and resolvers that validate DNSSEC reject unsigned answers for a
domain that still has a DS record, so the domain would stop resolving for many visitors.
:::

## Step 4: Point the host names you serve at Cloider

A target doesn't add DNS records, so each host name you route needs a record that sends it to Cloider's HTTPS entry
point: the same place every `cloider.app` subdomain resolves to.

| Host name | Record on `example.com` | Value |
| --- | --- | --- |
| `example.com` (the apex) | `A` with a blank name, added with the domain in step 1 | Cloider's HTTPS entry point |
| `www.example.com`, `shop.example.com`, any subdomain | `CNAME` with the name `www`, `shop`, ... | A free subdomain you hold, such as `acme-web.cloider.app.` |

The apex record is on the domain's **DNS records** list like any other, so you can change or delete it. A CNAME can't be
used at the apex, which is a rule of DNS itself; to point the apex at a host name elsewhere, use an
[`ALIAS` record](/domains/dns-records#alias-record). While the apex record still points at Cloider, an `A` or `ALIAS`
record you add with a blank name takes its place instead of being refused as a second one.

Add a CNAME for each subdomain. With the CLI:

```bash
cloider dns create example.com --type CNAME --name www --value acme-web.cloider.app. --ttl 3600
```

```text title="Output"
✓ Added CNAME record www -> acme-web.cloider.app.
```

In Terraform:

```hcl title="main.tf"
resource "cloider_dns_record" "www" {
  domain = cloider_domain.example.name
  type   = "CNAME"
  name   = "www"
  values = ["acme-web.cloider.app."]
  ttl    = 3600
}
```

:::note[Prefer CNAME records]
An A record stores a copy of an address, while a CNAME follows the free subdomain automatically. Use a CNAME for every
name except the apex.
:::

## Step 5: Route the domain with a target

A target sends requests for a path of the domain to an app or a cluster Service, or the whole domain to a bucket's
static website. This is what makes the domain serve something, and it switches the domain's status from `Pending` to
`Active`.

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

1. On the **Connect your apps** step, or on the domain's page under **Domains**, click **Add target**.
2. In **Add a new target**, choose the **Target type**: **App** to pick one of your apps, **Cluster** to pick a
   cluster, **Namespace**, **Service** and **Port**, or **Bucket** to pick a bucket whose website is on.
3. Leave **Path** as `/` to route the whole domain, and leave **Target path** empty unless you need to
   [rewrite the path](/domains/targets#rewrite-the-path).
4. Click **Save**.

</TabItem>
<TabItem value="cli" label="CLI">

To an app:

```bash
cloider target create example.com --app web
```

```text title="Output"
✓ Routed example.com/ to the app
```

To a Service in a cluster:

```bash
cloider target create example.com --cluster production --service shop/web --port 80
```

```text title="Output"
✓ Routed example.com/ to production/shop/web:80
```

To a bucket's static website:

```bash
cloider target create example.com --bucket acme-site
```

```text title="Output"
✓ Routed example.com/ to the bucket's website
```

</TabItem>
<TabItem value="terraform" label="Terraform">

```hcl title="main.tf"
# To an app, by its id from `cloider app list -o wide`
resource "cloider_target" "web" {
  domain = cloider_domain.example.name
  app_id = "w4d8hz"
}
```

```hcl title="main.tf"

  domain     = cloider_domain.example.name

}
```

```hcl title="main.tf"
# Or to a bucket's static website

  domain    = cloider_domain.example.name
  bucket_id = cloider_bucket.site.id

```

</TabItem>

## Step 6: Wait for DNS and HTTPS

Once the nameservers have switched and the name resolves to Cloider, Cloider requests a certificate for the host name
from Let's Encrypt. This usually takes a minute or two after DNS resolves. Until then, browsers show a certificate
warning for the domain. See [HTTPS certificates](/domains/https-certificates).

## Verify

Check each link of the chain, from the registry to the certificate:

```bash
# 1. The registry hands out Cloider's nameservers (for .com domains)
dig example.com NS @a.gtld-servers.net +noall +authority

# 2. Cloider's nameservers answer with your records
dig @ns1.cloider.com example.com A +short
dig @ns1.cloider.com www.example.com A +short

# 3. Your usual resolver sees the same answers
dig example.com A +short

# 4. HTTPS works and the certificate is for your domain
curl -sSI https://example.com
```

```text title="Output"
example.com.		172800	IN	NS	ns1.cloider.com.
example.com.		172800	IN	NS	ns2.cloider.com.
example.com.		172800	IN	NS	ns3.cloider.com.
example.com.		172800	IN	NS	ns4.cloider.com.
203.0.113.80
acme-web.cloider.app.
203.0.113.80
HTTP/2 200
```

In the dashboard, the domain appears on the **Domains** page with the status `Active`.

## Serve both example.com and www.example.com

A target routes the host name of the domain it belongs to. To serve `www.example.com` as well as `example.com`, add
`www.example.com` as a domain of its own and give it a target too. Its DNS record (the `www` CNAME from step 4) stays on
`example.com`.

```bash
cloider domain create www.example.com
cloider target create www.example.com --app web
```

The CLI prints the nameservers again for `www.example.com`. You don't need to change anything for it at the registrar:
`www.example.com` is answered by the nameservers of `example.com`.

Cloider routes both names to the same app, and each gets its own certificate. Cloider doesn't redirect one name to the
other. If you want `www` to redirect to the apex, do it in your app.

## Keep your current DNS provider

You can serve a domain from Cloider without moving its DNS. Skip step 3, and add the step 4 records at your current
DNS provider instead of in Cloider:

1. Add the domain to Cloider (step 1).
2. At your DNS provider, add a CNAME for each subdomain you serve, pointing at a free subdomain you hold, such as
   `acme-web.cloider.app`, and an A record for the apex with the address that subdomain resolves to (`dig +short
   acme-web.cloider.app A`).
3. Add targets in Cloider (step 5) and wait for the certificate (step 6).

Some providers, such as Cloudflare, accept a CNAME at the apex (Cloudflare calls it CNAME flattening), which saves you
from copying an address.

:::warning[Use DNS only mode with proxying providers]
If your DNS provider can proxy traffic, as Cloudflare does with the orange cloud, set the records that point at Cloider
to DNS only. A proxy terminates HTTPS itself and can stop Cloider from completing the certificate check for the domain.
:::

Records you add in Cloider aren't used while the domain's nameservers point elsewhere.

## Troubleshooting

| Problem | Cause and fix |
| --- | --- |
| `The domain already created by a different user, if you own this domain contact support` | Another Cloider account added the domain first. Contact [support](/account/support) |
| `Disallowed domain name` | Names under Cloider's own domains can't be added. Use a [free subdomain](/domains/free-subdomains) |
| `Domain name is a public suffix shared by many owners, add your own domain under it, such as example.co.uk` | A public suffix belongs to no one. Add the domain you registered under it |
| `This domain is under ..., which belongs to another Cloider account` | Another account holds a domain above this one, and its DNS records would answer for this name. Contact [support](/account/support) if you own it |
| `A domain under this one belongs to another Cloider account` | Another account added a name under this domain first. Contact [support](/account/support) if you own the domain |
| **Check Availability** stays disabled | The dashboard expects a name such as `example.com`, with a TLD of at least two letters. Remove `https://` and any path |
| `dig example.com` returns `NXDOMAIN` | The domain has no records in Cloider, or the registry still points at the old nameservers. See [Troubleshooting](/domains/troubleshooting#nxdomain-for-my-domain) |
| Email stopped arriving after the switch | The MX record wasn't copied. Add it in Cloider, see [Email DNS records](/domains/email-dns-records) |
| Certificate warning in the browser | The name doesn't resolve to Cloider yet, or the certificate is still being issued. See [HTTPS certificates](/domains/https-certificates) |
| `404` page on the domain | The name reaches Cloider but no target matches. Add a target for the host name and path |

More cases, with `dig` and `nslookup` checks, are in [Domains troubleshooting](/domains/troubleshooting).
