Email for a custom domain such as `you@example.com` depends on four kinds of DNS records: **MX** says where incoming
mail is delivered, **SPF** says which servers may send mail for the domain, **DKIM** publishes the key that signs your
outgoing mail, and **DMARC** tells receivers what to do with mail that fails those checks. Cloider doesn't host email,
but when your domain uses [Cloider's nameservers](/domains/nameservers) these records live in Cloider. This page
explains each record and gives complete setups for Google Workspace and Microsoft 365.

## At a glance

| Record | Type | Name | What it does | Example value |
| --- | --- | --- | --- | --- |
| **MX** | `MX` | blank (`@`) | Where mail for `@example.com` is delivered | `1 smtp.google.com.` |
| **SPF** | `TXT` | blank (`@`) | Which servers may send as `@example.com` | `v=spf1 include:_spf.google.com ~all` |
| **DKIM** | `TXT` or `CNAME` | `<selector>._domainkey` | The public key receivers check signatures with | `v=DKIM1; k=rsa; p=MIIBIjANBg...` |
| **DMARC** | `TXT` | `_dmarc` | The policy for mail that fails SPF and DKIM, and where reports go | `v=DMARC1; p=none; rua=mailto:dmarc@example.com` |
| **Verification** | `TXT` | usually blank | Proves to the provider that you control the domain | `google-site-verification=...` |

:::info[Example values]
The provider values on this page are examples taken from Google's and Microsoft's own setup documentation, current at
the time of writing. Your provider's admin console shows the exact values for your domain, and those always win: copy
them from there, especially DKIM keys and verification tokens, which are unique to you.
:::

## Before you begin

- A [custom domain](/domains/add-a-custom-domain) in Cloider. Free `cloider.app` subdomains can't have email records.
- The domain uses [Cloider's nameservers](/domains/nameservers), or will soon. Add the records first, then switch the
  nameservers, so mail keeps flowing.
- An account with a mail provider such as Google Workspace, Microsoft 365, Fastmail, Proton Mail or Zoho Mail, and its
  admin console open.

## How to enter email records in Cloider

A few Cloider rules matter for email records:

- **Record name**: blank for the domain itself, `_dmarc` for DMARC, `google._domainkey` for a DKIM key. Never the full
  name. See [What do I type as the record name?](/domains/dns-records#what-do-i-type-as-the-record-name)
- **One record per type and name**: several MX servers go in one `MX` record, one per line. An SPF policy and
  verification tokens at the apex go in one `TXT` record, one per line.
- **No quotes** around TXT values. Type `v=spf1 include:_spf.google.com ~all`, not
  `"v=spf1 include:_spf.google.com ~all"`.
- **Long DKIM keys** go in as one value. Cloider splits values over 255 characters into DNS strings for you.
- **TTL**: `3600` is a good value for email records, which rarely change.

## MX records: receive mail

An MX record lists the servers that accept mail for the domain, each with a priority. Senders try the lowest number
first and fall back to higher ones.

```text title="Value of the MX record (name blank)"
10 mx1.mail.example.net.
20 mx2.mail.example.net.
```

Without an MX record, mail to `you@example.com` bounces. With MX records for two providers, mail is split between them
unpredictably, so keep only your current provider's servers.

## SPF: who may send mail for the domain

SPF (Sender Policy Framework) is a TXT record at the apex that lists the servers allowed to send mail as
`@example.com`. It starts with `v=spf1`, lists the senders, and ends with what to do with everyone else:

```text
v=spf1 include:_spf.google.com include:mail.example.net ~all
```

| Part | Meaning |
| --- | --- |
| `v=spf1` | This is an SPF policy. Must come first |
| `include:_spf.google.com` | Also allow the servers in Google's SPF policy |
| `ip4:203.0.113.25` | Also allow this address, for example your own mail server |
| `~all` | Mark all other senders as suspicious (softfail) |
| `-all` | Reject all other senders (fail) |

:::warning[Exactly one SPF policy per domain]
A domain may have only one SPF policy. When you use several senders, such as Google Workspace and a newsletter
service, merge them into one policy with several `include:` parts. Two separate `v=spf1` values at the same name make
SPF fail for all your mail. Publish SPF as `TXT`, not with the retired `SPF` record type: Cloider returns both to
`TXT` queries, which would count as two policies.
:::

## DKIM: sign outgoing mail

DKIM (DomainKeys Identified Mail) lets receivers check that a message really came from your domain and wasn't changed.
Your provider signs outgoing mail with a private key and gives you the public key to publish at
`<selector>._domainkey.example.com`. The selector is chosen by the provider, for example `google` or `selector1`.

Providers publish DKIM keys in one of two ways:

- **A TXT record** with the key, such as Google Workspace: name `google._domainkey`, value
  `v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...`.
- **CNAME records** that point at keys the provider hosts and rotates, such as Microsoft 365: name
  `selector1._domainkey`, value `selector1-example-com._domainkey.acmeinc.onmicrosoft.com.`.

Enable DKIM signing in the provider's console after the record is published, since the provider checks the record
first.

## DMARC: the policy and reports

DMARC (Domain-based Message Authentication, Reporting and Conformance) is a TXT record at `_dmarc` that tells receivers
what to do with mail that fails both SPF and DKIM alignment, and where to send reports.

```text title="Value of the TXT record named _dmarc"
v=DMARC1; p=none; rua=mailto:dmarc-reports@example.com
```

| Tag | Meaning |
| --- | --- |
| `v=DMARC1` | This is a DMARC policy. Must come first |
| `p=none` | Only report. Start here |
| `p=quarantine` | Put failing mail in spam |
| `p=reject` | Reject failing mail |
| `rua=mailto:...` | Where daily aggregate reports go |
| `pct=25` | Apply the policy to 25 percent of failing mail, for a gradual rollout |

Start with `p=none`, read the reports for a few weeks to find every service that sends as your domain, fix their SPF
and DKIM, then move to `p=quarantine` and finally `p=reject`. Large mailbox providers expect bulk senders to publish at
least `p=none`.

## Set up Google Workspace

These are the records Google documents for Google Workspace. In the Google Admin console, the exact values for your
domain are under the domain setup and the Gmail authentication settings.

| Purpose | Type | Name | Value (example) |
| --- | --- | --- | --- |
| Verify the domain | `TXT` | blank | `google-site-verification=rXOxyZounnZasA8Z7oaD3c14JdjS9aKSWvsR1EbUSIQ` |
| Receive mail | `MX` | blank | `1 smtp.google.com.` |
| SPF | `TXT` | blank | `v=spf1 include:_spf.google.com ~all` |
| DKIM | `TXT` | `google._domainkey` | `v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...` (from the Admin console) |
| DMARC | `TXT` | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc-reports@example.com` |

The verification token and the SPF policy share the blank name, so they go in **one** TXT record with two lines.

```bash title="google-workspace.sh"
DOMAIN=example.com

cloider dns create "$DOMAIN" --type MX --ttl 3600 --value "1 smtp.google.com."

cloider dns create "$DOMAIN" --type TXT --ttl 3600 \
  --value $'google-site-verification=rXOxyZounnZasA8Z7oaD3c14JdjS9aKSWvsR1EbUSIQ\nv=spf1 include:_spf.google.com ~all'

# Paste the key from Admin console > Apps > Google Workspace > Gmail > Authenticate email
cloider dns create "$DOMAIN" --type TXT --name google._domainkey --ttl 3600 \
  --value "v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA..."

cloider dns create "$DOMAIN" --type TXT --name _dmarc --ttl 3600 \
  --value "v=DMARC1; p=none; rua=mailto:dmarc-reports@example.com"
```

## Other mail and sending services

Transactional and marketing services, such as the ones that send your app's password reset mail or newsletters, ask
for the same kinds of records:

- **An `include:` for your SPF policy.** Add it to your existing SPF value instead of creating a second policy:
  `v=spf1 include:_spf.google.com include:sendgrid.net ~all`.
- **DKIM records**, as `TXT` or `CNAME`, at the selectors they name.
- **A return path or bounce domain**, often a `CNAME` such as `bounce` or `em123`.
- **A verification `TXT`**, which goes on its own line of the TXT record at that name.

A `CNAME` can't share its name with another record. If a service asks for a `CNAME` at a name where you already have a
record, such as `mail`, choose another name in the service or remove the old record.

## Verify

Check what Cloider's nameservers answer:

```bash
dig @ns1.cloider.com example.com MX +short
dig @ns1.cloider.com example.com TXT +short
dig @ns1.cloider.com google._domainkey.example.com TXT +short
dig @ns1.cloider.com _dmarc.example.com TXT +short
```

```text title="Output"
1 smtp.google.com.
"google-site-verification=rXOxyZounnZasA8Z7oaD3c14JdjS9aKSWvsR1EbUSIQ"
"v=spf1 include:_spf.google.com ~all"
"v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA..." "...rest of the key..."
"v=DMARC1; p=none; rua=mailto:dmarc-reports@example.com"
```

`dig` prints TXT values in quotes, and a long DKIM key as several quoted strings: that is how DNS stores them, and mail
servers join them back together. Then use your provider's own check, such as the domain status in the Google Admin
console or the Microsoft 365 admin center, and send a test message to an address at another provider and look at its
authentication results (in Gmail, **Show original** shows `SPF: PASS`, `DKIM: PASS` and `DMARC: PASS`).

## Troubleshooting

| Problem | Cause and fix |
| --- | --- |
| `TXT record already exists for '@ (root)'. ...` | Add the new value as another line of the existing apex TXT record |
| `MX record already exists for '@ (root)'. ...` | Edit the MX record and put every mail server in it, one per line |
| `SPF record must start with 'v=spf1'` | You chose the `SPF` type. Use `TXT`, and start the value with `v=spf1` |
| `TXT record appears to be very long without spaces. ...` | Paste the whole DKIM value, including `v=DKIM1; k=rsa; p=` |
| `CNAME record cannot coexist with other record types for the same name: ...` | Another record uses that name. Remove it or pick another name |
| Mail fails SPF with `permerror` | The name has two SPF policies. Merge them into one `TXT` value |
| The provider says the record isn't found | Check the record name (`_dmarc`, not `_dmarc.example.com`), that the domain uses Cloider's nameservers, and wait for the TTL |
| `dig` shows quotes inside the value | The value was saved with quotes. Edit the record and remove them |
