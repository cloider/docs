A free subdomain is a name under `cloider.app`, such as `blog.cloider.app`, that you claim for your Cloider account at no
charge. It resolves to Cloider and is covered by Cloider's HTTPS certificate from the moment you claim it, so you can
put an [app](/apps/overview), a [Kubernetes Service](/kubernetes/expose-services) or a bucket's
[static website](/object-storage/static-websites) on it without touching DNS. This
page covers the naming rules, the availability check, claiming, routing and releasing a subdomain.

## At a glance

| | |
| --- | --- |
| **Parent domain** | `cloider.app` |
| **Format** | `<label>.cloider.app`, one label only: `blog.cloider.app`, not `api.blog.cloider.app` |
| **Label rules** | 2 to 63 characters; lowercase letters, digits and `-`; starts with a letter; doesn't start or end with `-` |
| **Cost** | No charge |
| **HTTPS** | Immediate, with Cloider's certificate for `*.cloider.app` |
| **DNS records** | Not editable. Use a [custom domain](/domains/add-a-custom-domain) for records |
| **Who can claim it** | The first account to claim a name holds it until it is deleted |
| **Status** | `Pending` until a [target](/domains/targets) routes to it, then `Active` |

## When should I use a free subdomain?

Use a free subdomain when you want a working HTTPS address now: for a new app, a staging environment, a preview, an
internal tool or a demo. Use a [custom domain](/domains/add-a-custom-domain) for your production site, for email, or
whenever you need DNS records.

You can use both at once. A common setup routes `example.com` and `acme-staging.cloider.app` to the same app or to
different ones.

## Naming rules

A free subdomain is `<label>.cloider.app`. The label must follow every rule below. The API checks them when you claim
or check a name, and the dashboard checks them as you type.

| Rule | Allowed | Refused | Message |
| --- | --- | --- | --- |
| Length 2 to 63 characters | `qa`, `acme-shop` | `a` | `Subdomain name must be at least 2 characters` |
| Lowercase letters, digits and hyphens only | `shop-2` | `shop_2`, `shop!` | `Subdomain name must contain only letters, numbers, and hyphens` |
| Starts with a letter | `v2-api` | `2-api` | `Subdomain name cannot start with numbers` |
| Doesn't start or end with a hyphen | `my-app` | `-app`, `app-` | `Subdomain name must not start with hyphens`, `Subdomain name must not end with hyphens` |
| No dots: one level only | `blog-api` | `api.blog` | `Subdomain name cannot contain dots (multi-level subdomains not allowed)` |
| No spaces | `myapp` | `my app` | `Subdomain name must not have spaces` |
| Ends in `.cloider.app` | `blog.cloider.app` | `blog.example.app` | `Invalid root domain name` |
| Not taken by another account | | | `This subdomain is already taken. Please try another one.` |

The CLI and the API lowercase a name before checking it, so `Blog.cloider.app` is claimed as `blog.cloider.app`. The
dashboard asks you to type it in lowercase.

:::tip[Pick a name nobody else has]
Short words such as `blog` or `shop` are often taken. Add your company or project name, as in `acme-blog`, or a short
random suffix. When you create an app, Cloider suggests `<app-name>-<4 random characters>`, for example `blog-x7k2`, for
exactly this reason.
:::

## Check whether a subdomain is available

The availability check tells you whether a name can be claimed, and why not if it can't. It only reads: it never
claims the name.

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

The **Subdomain** field on **Create App** checks the name as you type and shows either that it is available or the
reason it can't be used. See [Free subdomains for apps](/apps/domains).

On **Domains**, **Add Domain**, **Subdomain**, the **Check availability** button checks the name and, when it is free,
claims it straight away. See [Claim a subdomain](#claim-a-free-subdomain) below.

</TabItem>
<TabItem value="cli" label="CLI">

```bash
cloider domain check acme-blog.cloider.app
```

```text title="Output"
✓ acme-blog.cloider.app is available
```

When the name can't be claimed, the command exits with status `1` and says why:

```text title="Output"
Error: blog.cloider.app is not available: This subdomain is already taken. Please try another one.
```

</TabItem>
<TabItem value="terraform" label="Terraform">

Terraform has no availability check. A [`cloider_domain`](/terraform/resources/domain) whose name is taken fails at
`terraform apply` with the API's message. Run `cloider domain check` first if you aren't sure.

</TabItem>
<TabItem value="api" label="API">

```bash
curl -G https://cloider.com/api/domains/availability \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  --data-urlencode "domain_name=acme-blog.cloider.app"
```

```json title="Response"
{
  "domain_name": "acme-blog.cloider.app",
  "available": true,
  "reason": ""
}
```

When the name can't be claimed, `available` is `false` and `reason` is the message to show:

```json title="Response"
{
  "domain_name": "blog.cloider.app",
  "available": false,
  "reason": "This subdomain is already taken. Please try another one."
}
```

</TabItem>
<TabItem value="mcp" label="MCP">

```text title="Prompt"
Is acme-blog.cloider.app still free?
```

```json title="Tool call: check_domain_availability"
{"domain": "acme-blog.cloider.app"}
```

</TabItem>
</Tabs>

The check answers `You already own this subdomain. Connect it to the app from Domains instead.` for a name your account
already holds. That name is yours: add a target to it instead of claiming it again.

## Claim a free subdomain

Claiming a subdomain reserves it for your account with the status `Pending`. To serve something on it, add a
[target](/domains/targets) in the same step or later.

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

1. Open **Domains** in the sidebar, click **Add Domain** and choose **Subdomain**.
2. Type the label in **Subdomain Name**, for example `acme-blog`. The menu next to it shows the parent domain,
   `.cloider.app`.
3. Click **Check availability**. If the name is free, Cloider claims it and moves to **Connect your apps**.
4. Click **Add target**, choose **App**, **Cluster** or **Bucket** as the **Target type**, pick what to route to and
   click **Save**. See [Targets](/domains/targets) for every field.
5. Click **Add subdomain**. The button is enabled once the subdomain has at least one target.

<Screenshot
  src="/img/screenshots/domains/subdomain.webp"
  url="/dashboard/domains/subdomain"
  alt="The Choose subdomain page with acme-blog typed in Subdomain Name, .cloider.app selected, and the Check availability button"
  caption="Claiming a free subdomain. Check availability claims the name if it is free."
/>

Until a target is added, the page says **The subdomain will be activated once it's connected to an app with a
target.** If you leave at that point, the subdomain stays in your account as `Pending`.

</TabItem>
<TabItem value="cli" label="CLI">

```bash
cloider domain create acme-blog.cloider.app
```

```text title="Output"
✓ Claimed acme-blog.cloider.app
Route it with `cloider target create acme-blog.cloider.app --app <app>`.
```

The CLI claims any name that ends in a Cloider subdomain parent as a free subdomain, and adds anything else as a custom
domain. Route it to an app:

```bash
cloider target create acme-blog.cloider.app --app blog
```

```text title="Output"
✓ Routed acme-blog.cloider.app/ to the app
```

</TabItem>
<TabItem value="terraform" label="Terraform">

```hcl title="main.tf"
resource "cloider_domain" "blog" {
  name = "acme-blog.cloider.app"
}

resource "cloider_target" "blog" {
  domain = cloider_domain.blog.name
  app_id = "a7c2mq" # from `cloider app list -o wide`
}

output "url" {
  value = "https://${cloider_domain.blog.name}"
}
```

To build the name from the parent domain Cloider offers instead of writing `cloider.app`, read it from the
[`cloider_options`](/terraform/data-sources/options) data source:

```hcl title="main.tf"
data "cloider_options" "current" {}

resource "cloider_domain" "preview" {
  name = "acme-preview.${data.cloider_options.current.subdomain_roots[0]}"
}
```

</TabItem>
<TabItem value="api" label="API">

```bash
curl -X POST https://cloider.com/api/domains \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"domain_name": "acme-blog.cloider.app", "domain_type": "Subdomain"}'
```

```json title="Response"
{
  "domain_name": "acme-blog.cloider.app",
  "domain_type": "Subdomain",
  "status": "Pending",
  "created_at": "2026-10-20T09:12:44Z"
}
```

`domain_type` must be `Subdomain` for a free subdomain. If your account already holds the name, the API returns the
existing domain instead of an error.

</TabItem>
<TabItem value="mcp" label="MCP">

```text title="Prompt"
Claim acme-blog.cloider.app and route it to the blog app.
```

The agent claims the name, then routes it:

```json title="Tool call: create_domain"
{"domain": "acme-blog.cloider.app"}
```

```json title="Tool call: create_domain_target"
{"domain": "acme-blog.cloider.app", "app": "blog"}
```

</TabItem>
</Tabs>

### Claim a subdomain while creating an app

When you create an app from the dashboard, `cloider deploy` or `cloider app create`, Cloider claims a free subdomain
for it and adds the target for you, unless you turn this off. That is the fastest path for an app. See
[Domains for apps](/apps/domains).

## Verify

Open `https://acme-blog.cloider.app` in a browser once the target exists and the app or Service is running. From a
terminal:

```bash
curl -I https://acme-blog.cloider.app
```

```text title="Output"
HTTP/2 200
content-type: text/html; charset=utf-8
```

The domain's status is `Active` as soon as a target routes to it:

```bash
cloider domain list
```

```text title="Output"
DOMAIN                  TYPE          STATUS   CREATED
example.com             CustomDomain  Active   2026-10-12 09:14
acme-blog.cloider.app   Subdomain     Active   2026-10-20 09:12
```

## Can I add DNS records to a free subdomain?

No. Free subdomains don't take DNS records: the API answers `Can't add records on subdomains.`, and the domain page in
the dashboard shows targets only. A free subdomain always resolves to Cloider's HTTPS entry point, which is all a target
needs.

If you need records, for example to receive email or to verify a domain with another service, use a
[custom domain](/domains/add-a-custom-domain).

## Change an app's subdomain

A subdomain can't be renamed. To move to a new name:

1. Claim the new subdomain, for example `acme-blog-v2.cloider.app`.
2. Add a target that routes it to the same app or Service.
3. Check that the new address works.
4. Delete the old subdomain. See [Delete a domain](/domains/delete-a-domain).

```bash
cloider domain create acme-blog-v2.cloider.app
cloider target create acme-blog-v2.cloider.app --app blog
curl -I https://acme-blog-v2.cloider.app
cloider domain delete acme-blog.cloider.app
```

Once you delete a subdomain, any account can claim the name.

## Release a free subdomain

Delete the domain to release the name. Its targets are deleted with it, so the address stops serving your app.

- **Dashboard**: on **Domains**, open the domain's actions menu and click **Delete**.
- **CLI**: `cloider domain delete acme-blog.cloider.app`
- **Terraform**: remove the `cloider_domain` resource and run `terraform apply`.
- **API**: `DELETE https://cloider.com/api/domains/acme-blog.cloider.app`
- **MCP**: the `delete_domain` tool.

Deleting an app also deletes the free subdomains that were claimed with it, unless you choose to keep them. See
[Delete a domain](/domains/delete-a-domain) for the details.

## Troubleshooting

| Message | Cause and fix |
| --- | --- |
| `This subdomain is already taken. Please try another one.` | Another account holds the name. Choose another label |
| `You already own this subdomain. Connect it to the app from Domains instead.` | Your account already holds it. Add a target to it |
| `Invalid root domain name` | The name doesn't end in `.cloider.app`. Use a custom domain for other names |
| `Subdomain name cannot contain dots (multi-level subdomains not allowed)` | Only one label is allowed. Use `api-blog`, not `api.blog` |
| `Subdomain name cannot start with numbers` | Start the label with a letter: `v2-api`, not `2-api` |
| `Can't add records on subdomains.` | Free subdomains have no editable records. Use a custom domain |
| The address shows a `404` page | No target matches the path. Add a target, see [Targets](/domains/targets) |

More cases are in [Domains troubleshooting](/domains/troubleshooting).
