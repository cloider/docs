The concept pages explain how Cloider works underneath the buttons and commands. Read them once and the rest of the documentation makes more sense: why a paused cluster still costs a little, why an API token can't invite members, or why a resource has both a name and an id.

## At a glance

| Concept | In one sentence | Page |
| --- | --- | --- |
| The platform | Six products (apps, Kubernetes, databases, object storage, container registry, domains) on shared, managed infrastructure, used from five tools | [How Cloider works](/concepts/how-cloider-works) |
| Accounts and roles | Resources belong to an account; people reach it as the Owner or as Admin or Restricted members | [Accounts and roles](/concepts/accounts-and-roles) |
| Billing | Usage is metered continuously, priced per month, prorated to the second and invoiced monthly | [Billing model](/concepts/billing-model) |
| Lifecycle | Every resource moves through statuses such as Creating, Ready, Paused and Terminating | [Resource lifecycle](/concepts/resource-lifecycle) |
| Security | Isolation per account, HTTPS everywhere, hashed tokens, trusted sources and a shared responsibility model | [Security](/concepts/security) |
