Cloider is **pay as you go, from prepaid funds**: there are no plans to commit to, no upfront fees and no charge for idle machines. Cloider measures what each resource uses, prices it at monthly rates prorated to the second, and pays for it from the account's credits and balance as it is used. A monthly invoice records what the month cost and what paid for it. This page explains exactly what is measured and how it is paid.

Current prices are on [cloider.com/#pricing](https://cloider.com/#pricing), from `cloider pricing`, and from the public `GET https://cloider.com/api/pricing` endpoint. The [Pricing reference](/reference/pricing) lists every price and unit.

## At a glance

| | |
| --- | --- |
| **Model** | Pay as you go, metered continuously and paid from the account's funds as it is used |
| **Funds** | The account balance, which you top up, and credits. Credits are spent first, the one that expires soonest first |
| **Price unit** | Every price is per month. A billing month is 30 days (720 hours), and usage is prorated by the second |
| **Compute** | Apps and clusters pay for **compute units**: CPU or memory, whichever is larger at the current ratio |
| **Storage** | Cluster volumes, buckets and registry projects pay per GiB per month |
| **Databases** | A flat monthly price per plan, prorated; only storage while paused |
| **Free** | Domains, DNS, bucket requests and traffic, registry pushes and pulls |
| **Welcome credit** | $25 for a 14-day trial, which starts when you claim it in the dashboard |
| **No funds left** | Clusters, databases and apps pause. After 14 days without a top-up, resources are removed |
| **Invoices** | One per month for the month before, with a statement of the account balance, visible to the account Owner only |

## What is metered, product by product

| Product | Metered | How it is measured | Price kind |
| --- | --- | --- | --- |
| **Kubernetes cluster**: compute | CPU and memory of the cluster's running containers, including its Kubernetes control plane | Sampled every few seconds. Each container counts the larger of what it **requests** and what it **uses** | Cluster compute unit per month |
| **Kubernetes cluster**: volumes | Persistent volumes the cluster's PersistentVolumeClaims are bound to | Provisioned capacity in GiB, sampled every few seconds | Cluster volume, per GiB per month |
| **Kubernetes cluster**: load balancers | Services of type `LoadBalancer` that have a public IP | Time each one is active | Cluster load balancer, per month each |
| **App** | CPU and memory of the app's running [replicas](/apps/scaling) | Sampled every minute. Each replica counts the larger of what it is given and what it uses | App compute unit per month |
| **Database** | The database's plan | Time the database is **Ready**, at the plan's monthly price | Database plan price per month, per engine |
| **Database while paused** | The storage the plan provisioned | Time the database is **Paused** | Cluster volume rate, per GiB per month |
| **Bucket** | Data stored | GiB stored, sampled every few minutes and averaged over time | Bucket storage, per GiB per month |
| **Registry project** | Image data stored | GiB stored, sampled every few minutes and averaged over time | Registry storage, per GiB per month |
| **Domains, DNS records, targets** | Nothing | | Free |

### Compute units

Apps and clusters are billed in **compute units**. One compute unit is one vCPU, or the amount of memory the **CPU to memory ratio** pairs with one vCPU. A workload counts as whichever is larger:

```text
compute units = max(vCPU, memory / memory per vCPU)
```

For example, if the ratio is 1 vCPU to 3 GiB:

| Workload uses | vCPU | Memory / 3 GiB | Compute units billed |
| --- | --- | --- | --- |
| 0.5 vCPU, 1 GiB | 0.5 | 0.33 | 0.5 |
| 0.25 vCPU, 3 GiB | 0.25 | 1.0 | 1.0 |
| 2 vCPU, 6 GiB | 2 | 2.0 | 2.0 |

So a CPU heavy workload pays for its CPU and a memory heavy workload pays for its memory, never both. The current ratio and compute unit prices for clusters and apps are listed by `cloider pricing` (shown as `cpu to memory ratio`) and in the [Pricing reference](/reference/pricing). Clusters and apps have separate prices that can differ.

### Requests count, not only usage

For each running container, Cloider bills the **larger of its resource request and its actual use**, for CPU and for memory separately. A container that requests `500m` CPU and uses `100m` is billed for `500m`; one that requests `100m` and uses `300m` is billed for `300m`.

This makes requests a budget lever: set small requests for workloads that idle, and your bill follows what they actually use. In Kubernetes, requests are set per container under `resources.requests`.

### How a month is prorated

Every price is a monthly price, and a billing month counts as 30 days (720 hours). Usage is accumulated to the second, so:

- a resource that exists for half a month costs half its monthly price,
- an invoice shows hourly rates, which are the monthly price divided by 720,
- a database on a plan priced at a monthly amount costs that amount for 720 hours of being Ready.

### When prices change

Prices have effective dates. Each day's usage is priced at the rates in effect that day, so a price change applies from its date onward and never retroactively. If prices change during a month, the invoice splits that resource's lines into one line per price period.

## How usage is paid

Usage is paid as it happens, continuously through the day, from the account's funds:

1. **Credits** first. When the account has several, the one that expires soonest pays first.
2. Then the **account balance**, which the Owner tops up with [Add funds](/account/billing#add-funds).

The dashboard's **Balance** is the two together. There are no account plans and no limits on how many clusters, databases, buckets, registry projects or apps an account has: what it can run is limited only by its funds.

### Credits

A credit is an amount Cloider gives the account: the welcome credit, a promotion, a referral or a compensation. Each credit can have its own expiry date. What is left of a credit when it expires is no longer available. Credits pay for usage only, not for an amount the balance owes. See [Credits](/account/billing#credits).

### The welcome credit

A new account gets a 14-day trial with $25 of credit, as advertised on [cloider.com](https://cloider.com). The Owner claims it from a prompt in the dashboard, **Start trial**, and the 14 days start then. Until it is claimed, creating a resource fails with `Claim your $25 welcome credit from the dashboard to start your trial.` Usage during the trial is metered and paid exactly like any other usage, so the **Usage** page shows real costs. See [Create an account](/get-started/create-an-account#the-welcome-credit).

### When funds run out

Cloider emails the Owner 7 days and 1 day before the funds run out at the current usage. When they do, an account that has resources is suspended: its clusters, databases and apps are paused, while buckets and registry projects keep working. After 14 days suspended without a top-up, its resources are removed. Adding funds before that makes the account active again. See [What happens when your funds run out?](/account/billing#what-happens-when-your-funds-run-out).

## What does a paused resource cost?

Pausing stops compute but keeps data, so a paused resource costs only its storage, if it has any.

| Resource | While paused you pay for | You stop paying for |
| --- | --- | --- |
| **Kubernetes cluster** | Its persistent volumes (provisioned GiB) | Compute: the control plane and workloads stop running |
| **App** | Nothing | Compute: the app's containers stop |
| **Database** | The storage of its plan, at the cluster volume rate (`paused_price` in the pricing endpoint) | The plan price |
| **Bucket, registry project** | Can't be paused: data stored is billed until you delete it | |

While a resource is moving between states (**Creating**, **Pausing**, **Starting**...), a database accrues nothing; clusters and apps pay for whatever compute is actually running.

## What does a deleted resource cost?

Nothing from the moment it is deleted. Usage up to that moment stays on the month's invoice. Deleted resources stay visible on the **Usage** page, marked as terminated, for 60 days after their last usage, so you can see what they cost.

## Forecasts

The **Usage** page and `cloider usage` show, for each resource and for the account:

- **Cost to date (this month)**: what has accrued since the first of the month.
- **Forecast this month**: cost to date plus the rest of the month at the current rate.
- **Forecast next month**: a whole month at the current rate.

Forecasts assume that current usage, statuses and prices stay as they are. A database that is starting is forecast at its plan price, and one that is pausing at its storage price. See [Usage](/account/usage).

## Invoices

Cloider issues one invoice per account per month, for the month that just ended, and emails it to the Owner. The invoice is created early in the new month, once the last day's usage has been finalized. Since the usage was already paid from the account's funds, the invoice records it rather than asks for payment.

- An invoice is only created when the month's total is above zero.
- It has one **item per resource** (for example `Cluster: "production"`, `Database: "orders-db"`, `App: "blog"`, `Bucket: "acme-assets"`, `Registry project: "acme"`), each with lines that show the service, usage, unit, rate and cost.
- Units on the invoice: **Compute-Hour** for compute, **GB-Hour** for volumes and storage, **Hour** for load balancers and database plans.
- **Payment sources** show what paid for the usage: each credit and the account balance.
- A **Statement** shows the account balance over the month: opening balance, payments, what was charged to it, and the closing balance. When the closing balance is below zero, the invoice has an **Amount due** and its status is **Due** until a top-up pays it. Otherwise its status is **Paid**. See [Invoice status](/account/billing#invoice-status).

Only the account **Owner** can see invoices, in **Billing** in the dashboard, with `cloider billing`, or through `GET /api/billing` with the Owner's Read & Write API token. See [Billing](/account/billing).

## Who pays

Every resource in an account is paid from that account's funds, whoever created it. The account **Owner** adds funds and sees invoices. Members (Admins and Restricted) never pay for resources in accounts they don't own, and see the account's balance in the sidebar. See [Accounts and roles](/concepts/accounts-and-roles).

## Keep costs low

- **Pause what you don't use.** A paused cluster, app or database stops its compute. See [Resource lifecycle](/concepts/resource-lifecycle).
- **Right size requests.** Since requests count, small requests on idle workloads save money.
- **Delete load balancers you don't need.** Each active `LoadBalancer` Service is billed for the time it runs. Route domains with [targets](/domains/targets) instead.
- **Clean up storage.** Delete unused volumes, use [lifecycle rules](/object-storage/lifecycle-rules) on buckets and [retention policies](/container-registry/retention-policies) in the registry.
- **Watch the forecast.** Check [Usage](/account/usage) regularly, or script `cloider usage -o json`.
