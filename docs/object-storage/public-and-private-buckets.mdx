Every Cloider bucket is either **private**, so every request needs an access key or a presigned URL, or **public**, so anyone can download a file if they know its URL. New buckets are private. This page explains exactly what public read access allows and what it doesn't, how to switch a bucket between the two, and how to share single files from a private bucket.

## At a glance

| | Private bucket | Public bucket |
| --- | --- | --- |
| Download a file by its URL without a key | No | **Yes** |
| List the bucket's files without a key | No | No |
| Upload, overwrite or delete without a key | No | No |
| Download with an access key or a presigned URL | Yes | Yes |
| Shown in the dashboard as | **Private** | **Public** (list), **Public read** (Overview) |
| Typical use | User uploads, backups, internal data | Website images, CSS and JavaScript, public downloads |

## What does public read access mean?

Public read access means that anyone on the internet can fetch an object with a plain HTTPS `GET` request, if they know the object's key. Nothing else becomes public:

- **Listing stays private.** Nobody can ask the bucket "which files do you have?" without a key. A visitor has to know (or guess) the exact key.
- **Writing stays private.** Uploading, overwriting and deleting still need a read and write access key.
- **Settings stay private.** Visibility and policies are only changed with Cloider's tools. Versioning and lifecycle rules need Cloider's tools or a read and write access key.

A public file's URL is the bucket URL followed by the key:

```text
https://acme-assets.s3.eu-central-2.cloider.com/images/logo.png
```

The path style form works too:

```text
https://s3.eu-central-2.cloider.com/acme-assets/images/logo.png
```

You can use these URLs directly in HTML, CSS, emails and apps:

```html
<img src="https://acme-assets.s3.eu-central-2.cloider.com/images/logo.png" alt="Acme logo">
<link rel="stylesheet" href="https://acme-assets.s3.eu-central-2.cloider.com/css/styles.css">
```

:::warning[Public means public]
Every file in a public bucket can be downloaded by anyone who has its URL, including files you upload later. Keys are often guessable (`backup.sql`, `invoices/2026/0001.pdf`), and URLs leak through logs, browser history and shared links. Keep anything sensitive in a separate private bucket.
:::

## Make a bucket public or private

You can choose public read access when you [create a bucket](/object-storage/create-a-bucket), and change it at any time once the bucket is **Ready**. The change applies within moments.

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

1. Open **Buckets** in the sidebar and click the bucket.
2. Select the **Settings** tab.
3. Click the **Public Read Access** switch.
4. Confirm in the dialog: **Make public** in **Make Bucket Public**, or **Make private** in **Make Bucket Private**.

  caption="The Settings tab holds public read access, versioning and the delete button."
/>

The bucket's **Overview** tab and the Buckets list show the new access.

</TabItem>
<TabItem value="cli" label="CLI">

Show the current visibility:

```bash
cloider bucket visibility acme-assets
```

```text title="Output"
private
```

Make it public. The CLI asks for confirmation, `--yes` skips it in scripts:

```bash
cloider bucket visibility acme-assets public
```

```text title="Output"
Anyone will be able to read every file in acme-assets. Continue? [y/N] y
✓ Bucket acme-assets is now public
```

Make it private again:

```bash
cloider bucket visibility acme-assets private
```

```text title="Output"
✓ Bucket acme-assets is now private
```

</TabItem>
<TabItem value="terraform" label="Terraform">

```hcl title="main.tf"
resource "cloider_bucket" "assets" {
  name   = "acme-assets"
  public = true
}

# A file is read at <url>/<key>
output "assets_url" {
  value = cloider_bucket.assets.url
}
```

Set `public = false` (or remove it) and apply to make the bucket private. The change happens in place.

</TabItem>
<TabItem value="api" label="API">

```bash
curl -X PUT https://cloider.com/api/buckets/b7r2xw/visibility \
  -H "Authorization: Bearer $CLOIDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"public": true}'
```

```json title="Response"
{"success": true}
```

Send `{"public": false}` to make it private. The bucket's `public` field in `GET /api/buckets/b7r2xw` shows the current value.

</TabItem>
<TabItem value="mcp" label="MCP">

```

```

## Verify that a file is public

Request a file without any credentials. A public bucket answers `200`, a private one `403`:

```bash
curl -I https://acme-assets.s3.eu-central-2.cloider.com/images/logo.png
```

```text title="Output (public bucket)"
HTTP/2 200
content-type: image/png
content-length: 48213
```

```text title="Output (private bucket)"
HTTP/2 403
```

Listing the bucket without a key is refused even when it is public. The answer is an S3 error document:

```bash
curl https://acme-assets.s3.eu-central-2.cloider.com/
```

```xml title="Output"
<?xml version="1.0" encoding="UTF-8"?>
<Error><Code>AccessDenied</Code><Message>Access Denied</Message>...</Error>
```

In the dashboard, files in a public bucket have a **Copy public link** button in the **Files** tab.

## What happens when a bucket becomes private?

All public URLs stop working at once: requests without a key get `403 Access Denied`. Links you already shared, `<img>` tags on websites and URLs cached in apps break. Presigned URLs and access keys keep working.

A bucket whose [policy](/object-storage/bucket-policies) allows everyone (`"Principal": "*"`) can't be made private until those statements are removed: the API refuses with `The bucket's policy allows everyone ("*"), remove those statements first.` Edit or remove the policy first, then change the visibility.

## Make a public bucket listable

Public read access deliberately doesn't allow listing. If you want anyone to be able to list a public bucket's files (for example a public dataset or a downloads page generated by a tool), add a bucket policy that allows `s3:ListBucket` to everyone:

```json title="public-list.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicList",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::acme-assets"
    }
  ]
}
```

```bash
cloider bucket policy set acme-assets -f public-list.json
```

Statements that allow everyone are only accepted on a public bucket, and only for read actions. See [Bucket policies](/object-storage/bucket-policies).

## Share files from a private bucket

To share one file from a private bucket for a limited time, create a **presigned URL**. It works like a public link for that single file, and expires.

- In code, with any SDK. See [Create a presigned URL](/object-storage/sdks#create-a-presigned-url).
- With the AWS CLI: `aws s3 presign s3://acme-backups/reports/october.pdf --expires-in 3600 --profile cloider`.
- With rclone: `rclone link cloider:acme-backups/reports/october.pdf --expire 1h`.
- From the dashboard, the download button in the **Files** tab uses a presigned URL valid for one hour. It is meant for your own download rather than for sharing.

## Serve a website's assets from a public bucket

A public bucket is a simple way to host images, stylesheets, scripts and downloads for a website or an app:

1. Create a public bucket, for example `acme-assets`.
2. Upload the files with the right `Content-Type` and a `Cache-Control` header, for example with `aws s3 sync ./public s3://acme-assets --cache-control "public, max-age=86400" --profile cloider`.
3. Reference them by their URLs.

A bucket serves files, not a website: there is no index document (`/` doesn't return `index.html`) and no custom domain for a bucket. To serve a full site on your own domain, deploy it as an [app](/apps/overview). The guide [Static assets on object storage](/guides/static-assets-on-object-storage) walks through a complete setup.

## Troubleshooting

| Problem | Cause and fix |
| --- | --- |
| `403` / `Access Denied` on a file URL | The bucket is private, or the key in the URL is wrong (keys are case sensitive, and spaces must be URL encoded as `%20`) |
| `403` on the bucket URL itself (`/`) | Listing is never public. Add a policy allowing `s3:ListBucket` to `"*"` if you need it |
| `The bucket's policy allows everyone ("*"), remove those statements first.` | Remove the policy statements with `"Principal": "*"`, then make the bucket private |
| `The bucket must be ready to change its visibility.` | The bucket is still being created or is being deleted |
| `Another change to this bucket is in progress, try again in a moment!` | Another settings, policy or delete change to this bucket is running. Wait a moment and try again |
| `Couldn't change the bucket's visibility, try again in a moment!` | The change couldn't be applied, and the bucket kept its previous visibility. Try again |
| Browser shows the file as text or downloads an image | The file was uploaded with the wrong `Content-Type`. Upload it again with the right one |
| `making a bucket public needs confirming, pass --yes when not running in a terminal` (CLI) | Add `--yes` in scripts |
