An **API token** lets a script, a CI pipeline, the `cloider` CLI, the Terraform provider, the MCP server or your own code call the Cloider API without a browser. A token looks like `cldr_` followed by 40 random characters, works in one account, and acts as the member who generated it, with **Read** or **Read & Write** access.

## At a glance

| | |
| --- | --- |
| **Format** | `cldr_` + 40 characters, for example `cldr_xxxxxxxxxxxxxxxxxxxxxxxx` |
| **Scope** | One account, as the member who generated it, never more than that member's current role |
| **Access levels** | **Read** (only read requests) or **Read & Write** |
| **Shown** | Once, when generated. It can't be displayed again |
| **Expiry** | None. A token works until it is deleted, or its creator is removed or deactivated |
| **Limit** | 50 tokens per account; description up to 100 characters |
| **Managed in** | The dashboard only: **Access Control**, **API Tokens** |
| **Used as** | `Authorization: Bearer cldr_...`, `CLOIDER_TOKEN`, `CLOIDER_TOKEN_FILE`, or `cloider login` |

## Read or Read & Write?

| Access | Can | Can't | Use it for |
| --- | --- | --- | --- |
| **Read** | Every read (`GET`) request: list and show resources, usage, logs, kubeconfigs, database passwords | Create, change or delete anything, open terminals, run `exec`. Writes fail with `This API token is read only!` | Monitoring, dashboards, `terraform plan`, AI agents that only look |
| **Read & Write** | Everything its creator's role allows | Manage members and tokens, connect Git providers (dashboard only) | Deploys, CI, `terraform apply`, the CLI on your computer |

A token never has more access than its creator: a **Read & Write** token generated by an Admin acts as an Admin, and its access drops at once if the Admin is made Restricted. Restricted members can only generate **Read** tokens. The **Billing** endpoint only answers a **Read & Write** token generated by the Owner. See the [permission matrix](/concepts/accounts-and-roles#permission-matrix).

## Generate a token

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

1. Open **Access Control** in the sidebar and choose the **API Tokens** tab.
2. Click **Generate API token**.
3. Type a **Description** that says where the token will be used, for example `GitHub Actions deploy` or `terraform`. You'll see it in the token list later.
4. Under **Permissions**, choose **Read** (the default) or **Read & Write**.
5. Click **Generate API token**.
6. The **API token generated** dialog shows the token and a **Try it** `curl` command. Copy the token now: *This is the only time it is shown, and it can't be recovered*.
7. Click **I've saved the token**.

<TabItem value="cli" label="CLI">

`cloider login` generates a token for the CLI through the browser and saves it, so you don't need to copy one:

```bash
cloider login                 # Read and write or Read only, chosen in the browser
cloider login --read-only     # preselects Read only
```

For a token generated in the dashboard, pass it on stdin:

```bash
cloider login --with-token < token.txt
```

The CLI can't generate other tokens. See [Install the CLI](/get-started/install-the-cli).

</TabItem>
<TabItem value="terraform" label="Terraform">

Terraform can't generate API tokens. Generate one in the dashboard, then give it to the provider, preferably through the environment:

```bash
export CLOIDER_TOKEN=cldr_xxxxxxxxxxxxxxxxxxxxxxxx
terraform plan
```

See [Provider configuration](/terraform/provider-configuration).

</TabItem>
<TabItem value="api" label="API">

`POST /api/api-tokens` only accepts a signed in dashboard session, so a token can't be used to make more tokens. With a token it answers `403` with `This endpoint can't be used with an API token!`. Generate tokens in the dashboard.

</TabItem>
<TabItem value="mcp" label="MCP">

The MCP server can't generate API tokens. It uses the token `cloider login` saved. Use the **Dashboard** or **CLI** tab.

</TabItem>
</Tabs>

## Use a token

Send the token as a bearer token in the `Authorization` header of every API request:

```bash
curl -H "Authorization: Bearer $CLOIDER_TOKEN" https://cloider.com/api/clusters
```

The CLI and the Terraform provider read it from the environment:

```bash
export CLOIDER_TOKEN=cldr_xxxxxxxxxxxxxxxxxxxxxxxx
cloider cluster list
```

For a token kept in a file, such as a mounted secret, use `CLOIDER_TOKEN_FILE=/run/secrets/cloider-token` or the CLI's `--token-file` flag.

### In GitHub Actions

Store the token as a repository secret named `CLOIDER_TOKEN`, then expose it to the steps that need it:

```yaml title=".github/workflows/deploy.yml"
name: Deploy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    env:
      CLOIDER_TOKEN: ${{ secrets.CLOIDER_TOKEN }}
    steps:
      - uses: actions/checkout@v4
      - run: curl -fsSL https://cloider.com/install.sh | sh
      # the script installs to ~/.local/bin when /usr/local/bin is not writable
      - run: echo "$HOME/.local/bin" >> "$GITHUB_PATH"
      - run: cloider deploy --app blog
```

More in [CI/CD with GitHub Actions](/guides/ci-cd-with-github-actions) and [CI/CD with GitLab](/guides/ci-cd-with-gitlab).

### Check what a token can do

`GET /api/whoami` tells you who a token acts as, in which account, with which role, and whether it is read only:

```bash
curl -H "Authorization: Bearer $CLOIDER_TOKEN" https://cloider.com/api/whoami
```

```json title="Response"

  "user": {"first_name": "Jane", "last_name": "Doe", "email": "jane@acme.com", "picture": "https://...", "plan": "Paid", "trial_end_date": null, "suspended": false},
```

The **API Tokens** tab lists each token's **Description**, **Permission** (**Read** or **Read & Write**), **Created by** (for Owners and Admins), **Last used** and **Created at**. Owners and Admins see every token in the account; other members see only their own.

```bash
cloider token list
```

```text title="Output"
DESCRIPTION                     ACCESS        CREATED BY      LAST USED  CREATED           THIS CLI
Cloider CLI on janes-macbook    Read & Write  jane@acme.com   just now   2026-09-02 10:20  *

grafana                         Read          sam@acme.com    never      2026-10-01 14:30
```

The `*` marks the token the CLI is using. **Last used** is updated at most once a minute.

## Edit a token

You can change a token's description and its permission without generating a new one:

1. In **API Tokens**, click the pencil icon (**Edit**) on the token's row.
2. Change the **Description** or the **Permissions**.
3. Click **Save changes**.

Owners and Admins can edit any token in the account. A token can't be given **Read & Write** if its creator is Restricted.

## Delete (revoke) a token

Deleting a token revokes it: anything still using it loses access right away.

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

1. In **API Tokens**, click the delete icon on the token's row.
2. Confirm. The dialog warns that *Anything still using it loses access right away*.

</TabItem>
<TabItem value="cli" label="CLI">

`cloider logout` revokes the token the CLI is using and removes it from your computer. Other tokens are deleted in the dashboard.

```bash
cloider logout
```

```text title="Output"
✓ Logged out of profile default
```

`cloider logout --all` logs out of every profile.

</TabItem>
<TabItem value="terraform" label="Terraform">

Terraform can't delete API tokens. Use the **Dashboard** tab.

</TabItem>
<TabItem value="api" label="API">

A token can revoke itself, and only itself:

```bash
curl -X DELETE -H "Authorization: Bearer $CLOIDER_TOKEN" https://cloider.com/api/api-tokens/current
```

The answer is `204 No Content`. This works even for a **Read** token. Deleting any other token needs the dashboard.

</TabItem>
<TabItem value="mcp" label="MCP">

The MCP server can't delete API tokens. Use the **Dashboard** tab.

</TabItem>
</Tabs>

Tokens are also deleted automatically when their creator is removed from the account, and stop working while their creator is deactivated.

## If a token leaks

1. Delete it in **Access Control**, **API Tokens** straight away. It stops working on the next request.
2. Generate a new token with a new description and update the places that used the old one.
3. Check **Usage** and your resources for changes you didn't make.

The `cldr_` prefix makes leaked tokens easy to find with secret scanning tools.

## Troubleshooting

| Message | HTTP status | Cause and fix |
| --- | --- | --- |
| `Invalid or revoked API token!` | `401` | The token was deleted, mistyped, or its creator was removed or deactivated. Check `CLOIDER_TOKEN` and generate a new token if needed. |
| `This API token is read only!` | `403` | A **Read** token tried to change something. Use a **Read & Write** token. |
| `Terminals need a Read & Write API token!` | `403` | Terminals can't be opened with a **Read** token. |
| `This endpoint can't be used with an API token!` | `403` | Members, tokens, account switching and Git connections are dashboard only. |
| `An account can have up to 50 API tokens, delete one you no longer use!` | `400` | Delete unused tokens first. |
| `Description is required!` or `Description can be up to 100 characters` | `400` | Give the token a short description. |
| `Read & Write needs write access to this account, Restricted members can only have Read tokens` | `400` | Your role is Restricted. Choose **Read**. |

More in [Troubleshooting](/reference/troubleshooting) and [API authentication](/api/authentication).
