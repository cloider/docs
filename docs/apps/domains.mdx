Every Cloider app can have a free address such as `https://blog-x7k2.cloider.app`, claimed when you create the app, and
any number of your own domains such as `https://example.com` or `https://example.com/blog`. An app is put on a domain
with a **target**: a route from a path of the domain to the app. Cloider serves every address over HTTPS with a
certificate it manages. This page covers the free subdomain, custom domains, path routing, and what happens to domains
when an app is paused or deleted.

## At a glance

| | Free subdomain | Custom domain |
| --- | --- | --- |
| **Example** | `blog-x7k2.cloider.app` | `example.com`, `www.example.com` |
| **How you get it** | Claimed when you create the app, or later from **Domains** | Added in **Domains**, then delegated to Cloider's nameservers at your registrar |
| **HTTPS** | Automatic | Automatic, once the domain points at Cloider |
| **Routed to the app with** | A target on `/`, created for you | A target you add |
| **When the app is deleted** | Deleted with it by default | Kept; only its route to the app is removed |

- The app's **Address** on the **Overview** tab is its first domain: the free subdomain claimed when it was created, if
  it has one.
- The address answers once the first version is running. Before that the Overview says **live once the first build
  deploys**.
- Requests reach the app as plain HTTP on its port. Cloider terminates TLS in front of it.

## The free cloider.app subdomain

When you create an app, Cloider suggests `<app-name>-<4 random characters>.cloider.app` and checks that it is free as
you type. You can type your own label instead, with these rules:

- 2 to 63 characters: lowercase letters, digits and `-`.
- Starts with a letter, doesn't start or end with `-`, and has no dots.
- Not already taken by anyone.

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

On **Create App**, step **Configure your app**:

1. Type a label in **Subdomain**, for example `blog-acme`. The field shows **blog-acme.cloider.app is available** or why
   it can't be used.
2. Leave **Give this app a free subdomain** on.
3. Click **Create App**.

Turning **Give this app a free subdomain** off creates the app with no address; a dialog, **This app won't have an
address**, reminds you to connect a domain later.

</TabItem>
<TabItem value="cli" label="CLI">

`cloider deploy` and `cloider app create` claim `<name>-<4 random characters>.cloider.app` unless told otherwise:

```bash
cloider deploy --name blog --subdomain blog-acme       # blog-acme.cloider.app
cloider deploy --name blog --no-subdomain              # no address yet
```

Check a name first:

```bash
cloider domain check blog-acme.cloider.app
```

</TabItem>
<TabItem value="terraform" label="Terraform">

Claim a subdomain and route it to an existing app with `cloider_domain` and `cloider_target`:

```hcl title="main.tf"
resource "cloider_domain" "blog" {
  name = "blog-acme.cloider.app"
}

# The app's id comes from `cloider app list -o wide`
resource "cloider_target" "blog" {
  domain = cloider_domain.blog.name
  app_id = "a7c2mq"
}
```

</TabItem>
<TabItem value="api" label="API">


```bash

  -H "Authorization: Bearer $CLOIDER_TOKEN"
```

If the subdomain can't be claimed, the app is still created and the response carries a `subdomain_error`.

## Put an app on your own domain

To serve an app on a domain you own, add the domain to Cloider, point it at Cloider's nameservers, add DNS records for
the host names you serve, and add a target to the app.

1. **Add the domain.** In **Domains**, add `example.com` (or run `cloider domain create example.com`). Cloider shows the
   nameservers to use. See [Add a custom domain](/domains/add-a-custom-domain).
2. **Change the nameservers** at your registrar to the ones Cloider shows, and wait for the change to propagate. See
   [Nameservers](/domains/nameservers).
3. **Add DNS records** for the subdomains you serve. The domain itself comes with an `ALIAS` record that points at
   Cloider, and the target in step 4 points it at the app's free subdomain, but a target doesn't add records. Point `www` (or any subdomain) at your app's free subdomain with a `CNAME`, as
   [Add a custom domain](/domains/add-a-custom-domain) shows step by step.
4. **Route it to the app** with a target, as shown below. The app must have deployed: its status must be `Ready` (or
   `Paused`).

<Tabs groupId="interface" queryString>
<TabItem value="dashboard" label="Dashboard" default>

1. Open **Domains** in the sidebar and click your domain.
2. Click **Add target**. In **Add a new target**, set **Target type** to **App** and pick the app under **App**.
3. Set **Path** (`/` for the whole domain) and, optionally, **Target path**.
4. Click **Save**. The domain serves the app over HTTPS once its certificate is issued.

### Route paths to different apps

A domain routes each path to one target, and a path covers everything under it, so `/` catches whatever no longer path
does. For example, `example.com` can serve the `web` app on `/`, the `api` app on `/api` and the `blog` app on `/blog`:

```bash
cloider target create example.com --app web
cloider target create example.com --app api --path /api
cloider target create example.com --app blog --path /blog
```

By default a request reaches the app with its full path (`/api/users` arrives as `/api/users`). Set a **target path** to
rewrite the prefix, for example to serve the `api` app at `/api` while it handles requests at `/`:

```bash
cloider target create example.com --app api --path /api --target-path /
```

Now `https://example.com/api/users` reaches the app as `/users`. An app served under a path must generate links and
redirects relative to that path, or use the target path to strip it.

## See an app's domains

Every domain routed to the app is listed with it:

- **Dashboard**: the **Address** on the **Overview** tab, and each domain's page under **Domains**.
- **CLI**: `cloider app get blog` prints `URL` and `Domains`; `cloider app open blog` opens the URL in your browser.
- **API**: `url` and `domains` on `GET /api/apps/<id>`:

```json
{
  "url": "https://blog-x7k2.cloider.app/",
  "domains": [
    {"domain_name": "blog-x7k2.cloider.app", "domain_type": "Subdomain"},
    {"domain_name": "example.com", "domain_type": "CustomDomain"}
  ]
}
```

## Remove a domain from an app

Delete the target that routes the domain to the app, from the domain's page in **Domains**, with
`cloider target delete <target-id>`, or by deleting the `cloider_target` in Terraform. The domain itself stays yours.
To give up a free subdomain entirely, delete the domain. See [Targets](/domains/targets) and
[Delete a domain](/domains/delete-a-domain).

## Domains when an app is paused or deleted

- **Paused**: the domains and targets stay. The address keeps resolving but has no app behind it until you resume.
- **Deleted**: the app's free subdomains are deleted with it by default (the dashboard pre-selects them, and
  `cloider app delete --keep-domains` keeps them). A custom domain is never deleted with an app; it only loses its
  route to the app, and its other records and targets stay.

See [Pause, resume and delete](/apps/pause-resume-and-delete).

## Troubleshooting

| Message | Cause and fix |
| --- | --- |
| **This subdomain is already taken. Please try another one.** | Pick another label |
| **You already own this subdomain. Connect it to the app from Domains instead.** | The subdomain is already in your account. Add a target to it instead of claiming it again |
| **This app is not ready yet. Wait until it finishes deploying, then add the target.** | Targets need a deployed app. Wait for the first build to be `Ready` |
| **This path is already in use on this domain. Please choose a different path.** | Another target uses that path. Delete or update it, or pick another path |
| **This app's name is too long to be exposed on a domain.** | Apps with very long names can't be routed from a domain. Create the app with a shorter name, for example under 50 characters |
| The custom domain doesn't load | The nameservers aren't pointing at Cloider yet, the host name has no `A` or `CNAME` record on the domain, or the certificate isn't issued yet. See [Domains troubleshooting](/domains/troubleshooting) |
| `502` or an error page on the address | The app isn't answering on its port. See [Troubleshooting apps](/apps/troubleshooting) |
