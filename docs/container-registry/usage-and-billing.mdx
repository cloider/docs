The [Cloider Container Registry](/container-registry/overview) is billed only for the **storage** your images take, per GB per month, charged by the hour. Pushes, pulls and network traffic are free, and so are projects, tokens and policies. This page explains how storage is measured, where to see each project's usage and forecast, and how to keep the bill down.

## At a glance

| | |
| --- | --- |
| **What you pay for** | Stored image data, per GB per month, billed by the hour |
| **Free** | Pushes, pulls, traffic, projects, tokens, retention and immutability policies, the storage limit itself |
| **How it is measured** | Each project's stored size is sampled every few minutes; you pay for the average |
| **Storage limit** | 1 to 20 GB per project (5 GB by default). It caps what can be pushed; it isn't what you pay for |
| **Price** | See [Pricing](/reference/pricing), the new project form, or `cloider pricing` |
| **Where to see it** | A project's **Usage** tab, the account's [Usage](/account/usage) page, `cloider registry usage`, `cloider usage` |

## How is registry storage measured?

Every few minutes, Cloider reads how many bytes each project stores, as the registry counts it for the project's storage limit. These samples are averaged per day, and each day is charged as:

```text
daily cost = average GB stored that day × (hours billed / hours in a month) × price per GB-month
```

So a project that holds 2 GB for half a month and nothing for the other half costs the same as 1 GB for a whole month. Nothing is rounded up to a full GB or a full month.

What counts toward a project's storage:

- every image in every repository, tagged or untagged, until it is deleted,
- build caches pushed with `--cache-to type=registry` and attestation manifests added by buildx,
- Helm charts and other OCI artifacts.

The **apps project** (with the **Apps** badge) is measured and billed like any other project. Cloider keeps each app's last two deployed images there.

Open the project and go to the **Usage** tab. It shows:

- **Avg. Stored (This Month)**: the average GB stored this month, the figure you are billed on.
- **Stored Now**: the latest sample.
- **Cost to Date (This Month)**.
- **Cost Forecast**: **This Month** and **Next Month**, if the project keeps storing what it stores now.
- Two daily charts for the last 31 days: **Avg. Stored** and **Cost**, with today's forecast.

## The storage limit is a cap, not a price

Each project has a storage limit between 1 and 20 GB. It protects you from a runaway pipeline: a push that would take the project past the limit is refused. You don't pay for the limit, only for what is stored, so a 20 GB limit on a project storing 1 GB costs the same as a 5 GB limit.

Change the limit in the project's **Settings** tab, with `cloider registry set acme --storage-limit 20`, the `storage_limit_gi` Terraform attribute, or `PUT /registry/projects/<id>/settings`. See [Change a project's settings](/container-registry/create-a-project#change-a-projects-settings).

## How to lower the registry bill

1. **Set up a retention policy** that keeps only the images you need, for example the 10 most recent builds per repository and every release. See [Retention policies](/container-registry/retention-policies).
2. **Delete what you don't need** by hand: old repositories, test images, abandoned branches. See [Repositories and tags](/container-registry/repositories-and-tags).
3. **Use small base images**: `alpine`, `distroless` or `-slim` variants, and multi-stage builds that leave compilers out of the final image.
4. **Mind build caches**: a `mode=max` registry cache can be as large as the image. Keep one cache tag per repository, not one per branch.
5. **Build only the platforms you run**: an amd64 plus arm64 image stores both.
6. **Leave untagged images to the nightly cleanup**, or delete them right away if you need the space now.

## Billing, invoices and the free plan

Registry storage appears on your monthly bill with your other resources; see [Billing](/account/billing) and the [billing model](/concepts/billing-model). The free plan allows one project (the apps project isn't counted).
